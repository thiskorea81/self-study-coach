# 문항 제작 워크플로 — 효율화 가이드

이번 세션에서 23개 성취기준(수학 7 + 국어 10 + 영어 6)에 각 10~15문항씩,
총 287문항을 채운 실제 과정을 돌이켜보고, 다음에 콘텐츠를 더 늘릴 때
같은 품질을 더 빠르게 낼 수 있는 방법을 정리한다.

## 이번에 실제로 한 방식

1. 2015 개정 교육과정 국어/영어/수학과 원문 PDF를 한 번 내려받아 실제
   성취기준 코드·명칭을 추출 → `standards.json` 재구성 (1회, 재사용 가능한 작업)
2. `/loop`를 20분 간격 cron으로 설정, **매 실행마다 성취기준 1개**를 순서대로 처리:
   문항 설계 → (수학) 계산을 별도 스크립트로 재검증 → JSON 작성 →
   그 파일 하나만 구조 검증 → `npm run build` → `git commit && push` →
   `TaskUpdate`로 진행상황 기록
3. 23번의 배치를 전부 끝낸 뒤에야 국어/영어/수학 전담 서브에이전트(`.claude/agents/`)를 만듦
4. 다 끝난 뒤에야 저장소 전체를 한 번에 검사하는 스크립트(`scripts/verify-questions.js`)를 만들었고,
   그 과정에서 국어 3개 단원의 보너스 문항이 `standards.json`에 등록되지 않은
   실제 버그(성취기준 이름이 빈칸으로 표시됨)를 발견해 고쳤다.

## 발견된 비효율

| 지점 | 문제 | 영향 |
|---|---|---|
| 순차 처리 | 23개 성취기준을 하나씩, 매번 cron 간격을 두고 처리 | 실제 작업 시간보다 총 소요 시간이 훨씬 길어짐(20분×23회 ≈ 7시간대 vs 실제 작업은 그보다 훨씬 짧음) |
| 서브에이전트를 나중에 만듦 | 국어/영어/수학을 동시에가 아니라 순서대로(수학→국어→영어) 처리 | 병렬로 했으면 가장 긴 과목(국어 10개)만큼만 걸렸을 시간을 3과목 합친 시간(23개)만큼 씀 |
| 파일 구조를 나중에 바꿈 | 처음엔 `sample.json` 하나에 다 넣었다가, 문항이 늘어난 뒤 단원별 파일로 리팩터링 | 리팩터링 자체가 별도 작업 단계로 들어감 |
| 검증 스크립트를 매번 새로 씀 | 수학 배치마다 gcd/lcm, 인수분해 등을 즉석 스크립트로 재계산 | 매번 스크립트를 다시 설계하는 시간 소모 |
| 검증 범위가 파일 단위 | 그 배치의 파일 하나만 검사, 저장소 전체 일관성은 마지막에야 확인 | `standards.json` 미등록 코드 같은 문제를 끝날 때까지 몰랐음 |
| 커밋 전 체크리스트가 암묵적 | 매번 "검증→빌드→커밋→푸시" 순서를 손으로 되풀이 | 반복 노동, 순서를 건너뛸 위험 |

## 다음 번 효율화 방안

### 1. 서브에이전트를 맨 처음에 만들고 병렬로 돌린다
`.claude/agents/{korean,english,math}-agent.md`는 이미 있다. 다음에 콘텐츠를
늘릴 때는 시작하자마자 한 메시지에서 세 개를 동시에 호출한다:

> "korean-agent, english-agent, math-agent를 병렬로 돌려서 각자 맡은 과목의
> 남은 성취기준을 순서대로 다 채워줘. 배치마다 `scripts/ship.sh`로 검증·빌드·
> 커밋·푸시하고, 끝나면 결과를 요약해서 보고해줘."

세 에이전트가 각자 자기 과목만 처음부터 끝까지 이어서 처리하므로,
가장 오래 걸리는 과목(문항 수가 가장 많은 과목) 하나의 시간만큼만 걸린다.

### 2. 콘텐츠 규모가 예상되면 파일 구조를 처음부터 단원별로
`public/study-data/questions/{standardId}.json` 구조를 이미 채택했으니
그대로 유지한다. 새 단원을 추가할 때도 처음부터 이 구조로 시작하고,
"일단 합쳐두고 나중에 쪼개기"는 하지 않는다.

### 3. 검증은 항상 `scripts/verify-questions.js`로
매번 즉석 스크립트를 새로 짜지 말고, 이 파일을 확장한다. 새로운 성취기준
유형(예: 수학 새 단원, 새 과목)이 생기면 이 스크립트에 검사 규칙을 추가해
누적시킨다. 실행 한 번으로:
- 전역 ID 중복
- `answer` 키가 `choices`에 실제로 존재
- 선택지 5개
- `achievementCode`가 `standards.json`의 실제 코드인지(단, 코드가 여러 단원에
  걸쳐 재사용되는 것은 정상이므로 "존재 여부"만 검사하고 "소속 단원"은 강제하지 않음)
- 성취기준별 문항 수(10개 미만이면 경고)
를 한 번에 확인한다.

### 4. 배치마다 `scripts/ship.sh "커밋 메시지"` 한 줄로 마무리
"검증 → 빌드 → 커밋 → 푸시" 네 단계를 매번 손으로 반복하지 않는다.
이 스크립트가 순서를 강제하므로, 검증을 빠뜨리고 커밋하는 실수가 원천적으로 줄어든다.

### 5. `/loop` 대신, 병렬 에이전트 안에서 "자기 과목 전체를 이어서" 처리
20분 cron 간격은 "혹시 한 번에 너무 많이 시키면 안 되니까" 나눈 것이었지만,
실제로는 배치 하나당 작업 시간이 20분보다 훨씬 짧았다. 앞으로는:
- 서브에이전트에게 **"성취기준 1개씩" 대신 "네 과목 전체를 순서대로"** 맡긴다.
- 정말 작업량이 너무 커서 나눠야 한다면, `/loop`의 간격을 20분보다 짧게 하거나
  (예: 5분), 매 배치에 성취기준을 1개가 아니라 2~3개씩 묶어서 왕복 횟수를 줄인다.

### 6. 콘텐츠 정책·검증 규칙은 문서 하나로 계속 누적
`docs/DECISIONS.md`(설계 배경)와 이 문서(작업 방식)를 분리해서 유지한다.
새로운 규칙이 생기면(예: 저작권 정책, 난이도 기준) `DECISIONS.md`에,
작업 프로세스가 바뀌면 이 문서에 추가한다.

## 다음 번 체크리스트

1. `standards.json`에 새 단원/성취기준이 이미 정리돼 있는지 확인 (없으면 먼저 추가)
2. 세 서브에이전트(국어/영어/수학)를 **한 메시지에서 동시에** 호출, 각자
   "네 과목 전체를 성취기준 순서대로, 10~15문항씩, `scripts/ship.sh`로 배치마다
   마무리해줘"라고 지시
3. 다 끝나면 `node scripts/verify-questions.js`로 전체 저장소 한 번 더 확인
4. 필요하면 `docs/DECISIONS.md`에 이번에 새로 정한 규칙을 추가
